# 08 — Design Partner Program

**Version:** 1.0  
**Sources:** [`../business/BETA_PROGRAM.md`](../business/BETA_PROGRAM.md) · Manufacturing blueprint · Commercial pricing  
**Purpose:** Learn with the right executives — then convert to Production with evidence.

---

## Purpose

The Design Partner Program exists to:

1. Validate **daily executive habit** on Command Centre  
2. Prove Profile fit (Operations · Commercial · Manufacturing)  
3. Stress-test judgement quality with real operating tension  
4. Generate **publishable case evidence** (named or anonymised)  
5. Convert partners to paid Individual, Team, or Enterprise  

It is **not** free consulting forever, a custom Core fork, or a substitute for the product roadmap process.

---

## Selection criteria

### Must have

- [ ] Executive sponsor (CEO / COO / BU MD) committed for the pilot window  
- [ ] Named champion with weekly availability  
- [ ] Willingness to define three outcomes in Discovery  
- [ ] English-speaking; workable timezone overlap  
- [ ] Honest feedback — including what fails  

### Strong fit

- Primary ICP firmographics ([`../business/IDEAL_CUSTOMER_PROFILE.md`](../business/IDEAL_CUSTOMER_PROFILE.md))  
- Or Manufacturing / industrial OEM archetype (multi-factory, dealer channel, capital tension)  
- Board or leadership pressure on execution visibility  
- Copilot / chat already tried; judgement gap remains  

### Disqualifiers

- No executive sponsor  
- On-premise-only requirement  
- Expectation that Braltiq will customise Core for their industry  
- Unwillingness to share qualitative feedback or usage honesty  

**Capacity:** Prefer a small cohort (order of ~10 organisations in early programs) over a large, shallow beta — see Beta Program composition.

---

## Expectations

### Braltiq provides

- White-glove onboarding and weekly feedback cadence  
- Founder / product access for material issues  
- Clear success metrics and written pilot plan  
- Preferential path to Production packaging  
- Optional commercial consideration (e.g. Year-1 partnership terms) — document per deal; do not invent standing discounts in marketing  

### Design Partner provides

- Sponsor time and champion diligence  
- Outcomes, decisions, and operating context (within confidentiality)  
- Weekly 30-minute feedback  
- Permission pathway for case study (even if anonymised)  
- Conversion decision at pilot end — yes, no, or Enterprise path with reasons

## Pilot journey

| Phase | Window | Focus |
|-------|--------|-------|
| **Select** | Pre-pilot | Criteria check · NDA/MSA as needed · Profile choice |
| **Activate** | Week 1 | Kickoff · Discovery · first Command Centre habit |
| **Operate** | Weeks 2–6 | Artifacts compound · Council use · weekly feedback |
| **Prove** | Weeks 7–8 | Metrics review · qualitative interview · case outline |
| **Convert** | Exit + 2 weeks | Production package · credit card or Enterprise MSA |

Align week themes with [`../business/BETA_PROGRAM.md`](../business/BETA_PROGRAM.md) where helpful.

### Manufacturing / industrial pilots

- Use Manufacturing Executive Profile and pack context  
- Prefer Reality Lab–validated scenarios before exposing fragile reasoning  
- Never promise ERP replacement  
- Hitachi-class demos follow [`06_DEMO_PLAYBOOK.md`](./06_DEMO_PLAYBOOK.md)

## Success metrics

| Metric | Pilot target (illustrative) |
|--------|------------------------------|
| WAEx | ≥70% of enrolled execs by mid-pilot; ≥80% by exit |
| Command Centre opens | ≥4 / active exec / week |
| Decisions logged | Growing through pilot |
| NPS / pulse | ≥30 mid; ≥40 exit |
| Conversion intent | ≥50% “likely” mid; signed Production or LOI at exit for target partners |
| Case evidence | Draft story captured |

Exact cohort targets live in the Beta Program; commercial CS mirrors the same definitions.

## Feedback loops

| Cadence | Mechanism |
|---------|-----------|
| **Weekly** | 30-min champion call — bugs, judgement quality, habit |
| **Async** | Short pulse survey |
| **Product** | Triage P0/P1 within engineering cadence |
| **Internal** | Monday usage review; Friday retro |
| **Governance** | Feedback informs roadmap — does not entitle custom Core |

**Rule:** Partners influence priority through evidence of executive value — not feature voting.

---

## Case studies

### Capture

- Problem in customer language  
- Profile used  
- Morning ritual change  
- One decision or outcome story  
- Quote from sponsor (approved)  
- Metrics if shareable  

### Publish

- Named logo when approved  
- Otherwise vertical anonymised story (“Industrial OEM, APAC”)  
- Never invent results  

Minimum ambition for early GTM: **two publishable stories** before broad GA marketing push.

---

## Conversion to Production

| Path | When |
|------|------|
| **Individual Executive** | Single sponsor proved the rhythm |
| **Executive Team** | Leadership team shares one environment |
| **Enterprise** | Multi-entity, security, residency, or volume |

### Conversion conversation (exit)

1. Restate outcomes moved and habit evidence  
2. Confirm Profile  
3. Present Production packaging (AUD list) — no setup / implementation fee  
4. Offer annual option  
5. Ask for decision date  

Design Partner privileges (founders’ time, deep feedback rights) **narrow** after conversion; CS owns the ongoing relationship ([`07_CUSTOMER_SUCCESS.md`](./07_CUSTOMER_SUCCESS.md)).

## Confidentiality and trust

- Security review available for Enterprise-path partners  
- Public stories only with approval
